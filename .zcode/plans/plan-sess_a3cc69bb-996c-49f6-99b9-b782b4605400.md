# RevmeAI-Style Multi-Shop Smart Review Platform — Implementation Plan

## 1. TL;DR
Rebuild the current single-shop Vite SPA into a **multi-shop SaaS on Vercel + Supabase** that mirrors RevmeAI's core loop but without LLM costs. You (single admin) manage every shop: create shop → assign / generate a unique QR (initial pool of 10 + on-demand) → set its Google review URL and redirect behaviour → upload PNG logo → customer scans NFC/QR → lands on **your branded review helper page** (logo, star picker, 1–5 keyword chips, tone, template-generated draft, editable preview, **Copy & Open Google Reviews**) or, if AI toggle off, QR 302s straight to Google. All QRs encode your domain `https://domain.com/r/<8-char-code>` so the destination is editable forever without reprinting. Template engine (combinatorial slots, rating-aware) replaces LLM. Deployed Vercel-only — no Render backend. Premium minimal admin + customer UI, logo-aware QR with error correction H.

Your answers locked: **single admin (you only), no billing in MVP, branded page then Google**.

## 3. Architecture

### 3.1 Stack
Next.js 15 (App Router, TypeScript optional — JS is fine to match current code) + Tailwind 3 (existing config) + shadcn/ui (Radix primitives, copy-paste) + `qrcode` (server) + `qrcode.react` (client preview) + Supabase (Postgres + Auth + Storage) + Vercel primitives (`waitUntil` for analytics, edge middleware).

No LLM, no Cashfree/Stripe in MVP, no separate backend.

### 3.2 Routing Model (single Vercel project)
```
/                          Marketing (minimal hero + CTA to /login, SEO-ready)
/login                     Admin login (Supabase Auth email/password)
/dashboard                 Overview: metric cards, scans 30d chart, recent scans
/dashboard/shops           Shops table + Create shop
/dashboard/shops/[id]      Shop detail tabs: Overview / QR Codes / Analytics / Settings
/dashboard/qr              QR Pool: the 10 pre-generated codes + Generate new
/r/[code]                  QR/NFC entry point — see §3.3
/review/[code]             (alternative) branded customer page if you prefer /r/ to stay 302-only
/api/qr/generate           Server QR PNG/SVG generation
/api/qr/download           ZIP print kit
```
All dashboard routes protected by `middleware.ts` (`@supabase/ssr` refresh + redirect to `/login`). Public routes (`/r/[code]`, `/login`, `/`) are unprotected but rate-limited.

### 3.3 QR Entry Point Decision
Two behaviours controlled per shop by `shops.ai_enabled boolean`:
- **`ai_enabled = true` (default, branded):** `/r/[code]` **renders** the branded customer page directly (header brand, circular logo, star picker, chips, tone, generate, editable preview, Copy & Open Google). Its `Copy & Open` button 302s to `shops.google_review_url`. Scan is logged before render via `waitUntil`. This is RevmeAI's `r.` behaviour and satisfies "branded page then Google".
- **`ai_enabled = false`:** `/r/[code]` **302s** immediately to `shops.google_review_url` (no intermediate). Same code, instant redirect. Toggle in shop settings flips behaviour without reprinting.

The critical property for your NFC card in the screenshot: the printed QR/NFC always stores `https://yourdomain.com/r/AbC123x4` — never the Google URL. Editing `google_review_url` in the dashboard instantly moves every scan, no reprint. Print size: 1024px PNG, error correction H, logo overlay ≤22% with white padding, margin 2, min 2×2 cm.

### 3.4 Data Model (Supabase, shared-schema, single admin)
Keep it minimal for single-admin MVP; add `organizations` later when you need multi-owner.

```sql
profiles         (id uuid PK FK auth.users, email text, created_at)
shops            (id uuid PK, slug text unique, name text not null, description text,
                  google_review_url text not null, google_place_id text,
                  logo_url text, address jsonb, city text, category text,
                  ai_enabled bool default true, keywords jsonb, -- override defaults
                  is_active bool default true, created_at timestamptz)
qr_codes         (id uuid PK, code text unique not null, -- 8-char nanoid, what is encoded
                  shop_id uuid FK shops nullable, label text, -- "Counter NFC", "Table 1"
                  type text check (type in ('qr','nfc')) default 'qr',
                  scans_count int default 0, is_active bool default true, created_at)
analytics_events (id uuid PK, qr_code_id uuid FK qr_codes, shop_id uuid FK shops,
                  event_type text check (event_type in ('scan','copy_open_google')),
                  ip_hash text, user_agent text, country text, city text, device text,
                  created_at timestamptz default now())
```
Buckets: `shop-logos` (public, per-shop folder `shop-logos/<shop_id>/<uuid>.png`), `qr-assets` (optional cache). `review_templates` table is deferred — templates stay in `src/lib/templates.js` for MVP and move to DB only if you want non-dev editing.

Indexes: `shops.slug`, `qr_codes.code`, `qr_codes.shop_id`, `analytics_events(shop_id, created_at desc)`.

### 3.5 RLS (required)
Enable RLS on all tables. Public needs read for the branded page / redirect, admin needs full access.

- Helper: `is_admin()` = `(select auth.uid()) is not null` for single-admin; later replace with org membership check.
- `shops`: public `select where is_active = true`; authenticated `all using (auth.uid() is not null)`.
- `qr_codes`: same split.
- `analytics_events`: public **no select**; public **insert** denied from anon client — inserts only via Route Handler using `service_role` + `waitUntil`. Admin `select where true` (authenticated).
- `storage.objects`: `shop-logos` public read; insert/update/delete only via server action with `service_role` (client uploads go through server action that validates `image/png|jpeg|webp`, ≤2 MB, server-generated filename, then `admin.storage.from('shop-logos').upload`).

Never expose `SUPABASE_SERVICE_ROLE_KEY` to the client. Only `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` are public.

### 3.6 Logo PNG Flow
Admin Settings → drag PNG → client calls Server Action with `File` → server validates type/size → `supabaseAdmin.storage.from('shop-logos').upload(shop_id/uuid.png)` → `getPublicUrl` → `update shops.logo_url` → customer page renders `<img>` + QR generator overlays centered logo. Supabase Image Transformations (`?width=200&quality=80`) for admin thumbnails.

## 5. Review Generation Without LLM
Keep `src/lib/templates.js` and enhance: rating-aware banks (5★ enthusiastic, 4★ "great but", ≤3★ polite constructive — never fake-neg), spintax `{really|truly}`, optional segments `[really ]`, combinatorial slot filling (4 slots × 10 options ≈ 10k+ combos per tone), per-shop keyword injection from `shops.keywords`, length variation (short 30% / medium 50% / long 20%), post-process `a/an`, capitalise, vary emoji ≤20%, deduplicate. `generateReview({ chips, tone, stars, shopName })` stays the only call site — swapping to LLM later is one function change. UI copy must read "Draft — edit before posting" to stay compliant (same as RevmeAI disclaimer: reviews should be from genuine customers).

## 7. Build Sequence (ordered, no rework)

1. **Init Supabase:** Create project → run `schema.sql` + Storage buckets (`shop-logos` public) → seed 10 `qr_codes` with random `code` (unassigned `shop_id = null`) → create admin user → test RLS.
2. **Migrate to Next.js on Vercel:** `npx create-next-app` overlay (or convert Vite in place), port `tailwind.config.js` globs to `app/**/*`, move existing components verbatim, add `middleware.ts` + `lib/supabase/*`, wire `NEXT_PUBLIC_SUPABASE_URL/ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (Vercel env, server only), `NEXT_PUBLIC_SITE_URL`.
3. **Auth + Dashboard shell:** Login page + protected `dashboard/*` + empty states + skeletons.
4. **Shops CRUD:** List, create, edit — fields: name, slug (auto), Google review URL (validate `https://` and google domain), Place ID optional, logo PNG upload via server action, address/category, keywords override (comma-separated), `ai_enabled` toggle. Save → Supabase.
5. **QR Pool:** Display 10 seeded codes as cards with live `qrcode.react` preview of `SITE_URL/r/code`, Assign shop dropdown (`update qr_codes.shop_id` + `label`), Generate new code (nanoid 8, `insert`), Download PNG 1024px (server `qrcode` → buffer) with SVG option, Deactivate, copy link.
6. **Customer funnel:** `/r/[code]` server component fetches `qr_codes` join `shops` → if `shop.ai_enabled` render branded page (reuse current `App.jsx` UI as child, data from DB), else `redirect(shop.google_review_url, 302)`. Wire Generate → templates with `shop.name`, Copy & Open → clipboard + `waitUntil(admin.from('analytics_events').insert({event_type:'copy_open_google'}))` + `window.open(review_url)`, HelpModal fallback, scan event insert on page load.
7. **Analytics + polish:** `recharts` area/bar for scans 30d, Recent scans table, responsive pass (44px targets, keyboard, focus rings), LCP <1.5s, bundle check, rate-limit `/r/[code]` (Upstash or simple in-memory) to block scan spam, production `vercel --prod` with custom domain, NFC write guide (`NTAG213 NDEF URI https://domain.com/r/<code>`), QR print verification on Android/iOS.

## 8. Risks & Mitigations

- **Placeholder Place ID going live:** Guard `ShopForm` validator + dashboard banner if `google_review_url` missing or not a Google URL.
- **Clipboard / popup blocked (iOS):** Existing `textarea + execCommand` fallback + `HelpModal` with selectable textarea + manual "Open Google Reviews" link — keep as is.
- **Scan spam / anon insert abuse:** Never let anon insert analytics; use `service_role` in route handler with `waitUntil` + IP hash, add rate limit 20 req/min/IP.
- **QR logo unreadable:** Enforce H correction + white padding + max 22% overlay + test every generated QR with a scanner before download.
- **Single-admin assumption:** Use `auth.uid() IS NOT NULL` for now; plan's schema already supports adding `organizations` + `organization_members` later without migration.
- **SEO (RevmeAI's Flutter problem):** Next.js SSR marketing + `/r/[code]` with `generateMetadata` using `shops.name` avoids invisible SPA content.
